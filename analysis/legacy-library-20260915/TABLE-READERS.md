# Native AZ playlist/track reader trace (bounded)

Private EP147 SHA-256: `736bdc9322c00e5770af459c92cace33d8680825c07f00f909f74dfc473a77a6`. Addresses are ELF virtual addresses; `.rodata` file offsets are VA minus `0x400000`. Reproduce disassembly with `llvm-objdump -d --triple=aarch64 --start-address=... --stop-address=... EP147`. Static findings do not establish a working output database.

## Important schema split

EP147 contains **two** Rekordbox SQLite reader families. The local `Source/Domain/MusicLibrary/Server/Rekordbox/DataBase/SQLite/SqlitePlaylist.h` source string is VA `0x284b8d8`, with local fields such as `playlist_id` (VA `0x284bda8`), `playlist_id_parent` (`0x284bd90`), `sequenceNo` (`0x284ba18`), and `trackNo` (`0x284ba78`). Its local track source is `.../SQLite/SqliteTrack.h` at `0x284bbf8`, with lowercase/snake-case fields including `content_id`, `fileName`, `fileType`, `bpmx100`, `analysisDataFilePath`, and artist/album IDs nearby.

The other family has source string `.../DataBase/CloudSqlite/CloudSqlitePlaylist.h` at VA `0x285c5c0`. Its SQL literals use `djmdPlaylist` (`0x285c650`), `djmdSongPlaylist` (`0x285c660`), and `djmdContent` (VA `0x285be80`). Xrefs to `djmdPlaylist` cluster at `0x127d648`, `0x127d920`, and `0x1282690`; xrefs to `djmdSongPlaylist` include `0x1275360`, `0x127d42c`, and `0x1281de4`. Those CloudSqlite names must **not** be copied into a claimed minimum local USB OneLibrary schema. A string inventory by itself conflates the two families.

## Local read evidence

The local row getter at `0x1181340` loads literal `playlist_id` (`0x1181344-0x1181348`), searches a name-to-column vector with `0x2312430` at `0x1181394`, and only if a matching column and active statement are present calls `sqlite3_column_int64` at `0x11813bc`; otherwise it returns zero (`0x11813e0`). Adjacent local getter at `0x1181418` loads `sequenceNo` (`0x118141c-0x1181420`) and follows the same column-name lookup pattern. Local playlist construction at `0x1184f60` looks up an entity in the database metadata (`0x1184fa4` calls `0x11829c0`), forms a `playlist_id` filter through `0x1178ba0` at `0x1184fd4`, passes it to a query builder at `0x1184fe8`, and requests a row at `0x1185008`. This is a concrete playlist-ID read path, although the complete generated SQL and exact global entity-name selector have not yet been reconstructed.

For track membership, local matching code constructs a `content`/`playlist_content` join. The literal `content.content_id = playlist_content.content_id` is VA `0x284c2a8` (file offset `0x244c2a8`) and loaded at `0x11970d4-0x11970dc`; a separate literal `( playlist_id = %u AND sequenceNo <= %u )` at VA `0x284c2e0` is loaded at `0x1197160-0x1197168`. The code constructs a join/matching object beginning at `0x1197048`, using dynamic table metadata lookup `0x11829c0` at `0x11970ac` and `0x11970cc`. This ties playlist membership to `content_id` and demonstrates a `sequenceNo` bound in the **local** family; exact result ordering remains unproven. It is stronger evidence than nearby cloud `djmdSongPlaylist.TrackNo` literals, but does not yet give a complete CREATE TABLE definition.

The local track row code uses string-field metadata rather than hard-coded ordinal assumptions. For example `SqliteTrack.h` VA `0x284bbf8` has code xrefs at `0x118b09c`, `0x118b148`, and `0x118b3dc`, while the local `trackNo` field getter has an xref at `0x1196f24-0x1196f28` and reads via `sqlite3_column_int64` at `0x1196f74` after a metadata lookup. Native getter fallback can return zero for missing fields, so field-string presence is an accessed-field lead, **not** proof every named column is required to mount.

## Current minimum and unresolved acceptance

The native DB constructor's required SQL prepare is `SELECT * FROM property` (see `ACCEPTANCE.md`). Later prepared-playlist reads demonstrably rely on local-style `playlist_id`, `sequenceNo`, `content_id`, and a `content`/`playlist_content` join. The local `playlist` entity name, full local track SELECT list, ordering clause, and which missing columns cause a hard browse failure remain unresolved because readers generate SQL from an entity/column metadata layer. The bounded trace does not justify a fixed minimum CREATE TABLE schema or a promise that old `export.pdb` playlists will browse. A credible converter or native adapter must next reconstruct the dynamic entity selectors and query builder, validate ordered membership and track rows against a locally owned OneLibrary sample, then test on AZ hardware with a writable overlay. No sample DB, generated output, firmware, or Pi was used here.
