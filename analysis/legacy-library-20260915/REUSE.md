# Reuse assessment for AZ legacy Rekordbox support (source inspection, 2026-09-15)

BiteDJ checkout inspected: commit `326f74b7574af00aebc17da261de277c265801a6`; source paths below refer to that checkout. RX3 output paths refer to the separately retained research workspace, not required installation paths.

The target is native AZ prepared-library browsing from an old `export.pdb` USB. [REPORT.md](REPORT.md) confirms EP147 selects a SQLite mount first when its upstream selector `w5` is zero, then falls back to NoDB if the `PIONEER`/`.PIONEER` + `rekordbox` directory or derived `exportLibrary.db` file fails initial checks. The root prefix, exact derived absolute file path, and `w5` producer remain unknown. Existing BiteDJ and RX3 work can supply **legacy input parsing and validation patterns**; neither presently generates an AZ-accepted OneLibrary database.

For a native converter, the reusable portion ends at a validated intermediate record set: source track ID; audio and ANLZ path; title/artist/etc.; playlist ID, parent and ordered membership; cue bank/slot/time/end/color/label; beat-grid metadata; and explicit parse failures. The BiteDJ reader supplies most of these inputs, but `exportExt.pdb` linkage and complete legacy cue coverage need fixture-backed inspection. The RX3 overlay pattern can inform a PC-only private candidate tree while retaining the original USB export and music unmodified.

The AZ output half remains missing. A legitimate Device Library Plus fixture is needed to identify `exportLibrary.db` SQLite schema, version/property rows, playlist and track IDs, cue/analysis relations, indexes, file paths, and any encryption/signature or sidecar requirements. EP147's successful filesystem gate does **not** prove schema acceptance. We also need to finish the AZ creator caller trace for `w5` and confirm the full path generated by `0x234fe90`; the visible-vs-hidden PIONEER choice is already traced to `w4`/member `x19+0x20`, but its source mode is unknown. First acceptance should use a removable copied fixture in an isolated PC launch and compare native browser playlist/cue state against the legacy source record set. Only then could a custom image claim old-library support.

No BiteDJ, RX3, firmware, USB or Pi files were changed for this assessment.
