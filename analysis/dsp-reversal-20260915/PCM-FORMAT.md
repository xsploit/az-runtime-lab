# IRQ8 integer-to-float format checkpoint

IRQ8 calls `0x1181a310` at `0x1181aed8` with the normalized 0/1 DMA-buffer selector described in `BUFFER-CONSUMERS.md`. The routine forms a source address from `0x11800c00 + 704*selector` at `0x1181a398`–`0x1181a3c0`, then enters an `SPLOOPD` at `0x1181a3d4`. Its two explicit `LDW` lanes (`0x1181a3d6`, `0x1181a3da`) step their source pointers by 8 bytes; `B0=22` then `ADD -1` sets `ILC=21` (`0x1181a3c2`–`0x1181a3ce`), consistent with 22 scheduled loop iterations per pass. `B18` starts at 1 (`0x1181a318`), increments after the loop (`0x1181a480`), and is compared with 3 before a return/repeat decision (`0x1181a484`–`0x1181a48c`). This identifies a small fixed lane loop, but complete element counts require the compact software-pipeline schedule, including prologue/epilogue, to be reconstructed.

The visible input conversion is **signed**. Each loaded 32-bit word passes through `SHR ... ,0x8` (`0x1181a3e2` on B side, `0x1181a3ec` on A side) and `INTSP` (`0x1181a3e4`, `0x1181a3f4`). [TI's C67x instruction guide](https://www.ti.com/lit/ug/spru733a/spru733a.pdf) defines `SHR` as arithmetic right shift and `INTSP` as signed integer-to-single-precision conversion. This supports a **32-bit signed container with eight low bits discarded before floating conversion**. A left-aligned signed 24-bit PCM sample is one plausible producer format, but the SPI/McASP setup and this consumer do not independently prove that producer encoding or byte order.

The conversion does more than a simple `float(input >> 8)`. It manipulates the `INTSP` result's bit fields with `AND`, `EXTU`, `CMPLTU`, and `OR` (`0x1181a3f8`–`0x1181a434`), then applies `MPYSP` with coefficient register `A17` on both sides (`0x1181a438`, `0x1181a440`). `A17` is set under predicates at `0x1181a358`–`0x1181a394`, so the multiplier is mode-dependent. The float outputs are stored by `STW` at `0x1181a446` and `0x1181a44a` through advancing pointers `B4` and `A5`. The A-side pointer incorporates the constructed floating-state base `0x11839498` (`0x1181a3a4`, `0x1181a3b8`, `0x1181a3cc`); another base `0x11839390` is constructed at `0x1181a3a0`/`0x1181a3b0`, but the exact B-side store pointer provenance is unresolved from this compact packet. Both are DSP state addresses, not verified final audio output addresses.

An exact arithmetic formula and numeric normalization factor are **not established**. The predicated `A17` setup, bit-field correction logic, and `SPLOOPD` prologue/epilogue need scheduled data-flow reconstruction. It would be premature to implement this as `sample / 2^23`, assign a lane to a deck, or claim channel count from the two visible loads alone. The verified reusable software-mixer boundary is narrower: AZ DMA receives 32-bit McASP words into alternating 704-byte buffers; this IRQ8 routine shifts those words right by eight and converts signed integers into single-precision state values before further processing.
