# McASP receive buffer and consumer checkpoint

The McASP0 RX channel's base PaRAM set 0 transfers one 704-byte programmed block to `0x11800c00` (see `IRQ8-TRIGGER.md`). Its `LINK=0x4400` points to PaRAM set **32** at `0x01c04400`. The linked set is configured at `0x11816598`–`0x118165cc`: `OPT=0x00100084` at `0x118165a0`, `SRC=0x01d02000` (McASP0 data) at `0x118165a2`, `ACNT/BCNT=0x00040004` at `0x118165ae`, `DST=0x11800ec0` at `0x118165b4`, `BIDX=0x00b00000` at `0x118165c2`, `LINK=0x00044420` (set 33) at `0x118165c6`, `CIDX=0x00040000` at `0x118165c8`, and `CCNT=44` at `0x118165cc`. Its destination is **704 bytes after** `0x11800c00`, so the two buffers have the same configured span without overlap.

The next linked PaRAM set **33** uses destination `0x11800c00` again: `OPT=0x00100204` at `0x118165d2`, `SRC=0x01d02000` at `0x118165d8`, `ACNT/BCNT=0x00040004` at `0x118165e0`, `DST=0x11800c00` at `0x118165e8`, `BIDX=0x00b00000` at `0x118165f0`, `LINK=0x00044400` (set 32) at `0x118165f2`, `CIDX=0x00040000` at `0x118165fa`, and `CCNT=44` at `0x11816608`. This is a **static ping-pong recurrence**: set 0 -> set 32 -> set 33 -> set 32, alternately receiving at `0x11800ec0` and `0x11800c00`. Set 32's `OPT` also has `TCINTEN` bit20 and `TCC=0`; set 33's `OPT` likewise has bit20 and TCC0. Both linked sets are AB synchronized (bit2). [TI's EDMA guide](https://www.ti.com/lit/ug/spruh91b/spruh91b.pdf) describes automatic PaRAM reload through LINK after completion. Static configuration does not establish live clock rate or underrun behavior.

There is a direct IRQ8 processing call to a buffer reader. The interrupt wrapper calls `0x1181a310` at `0x1181aed8`. Its `A4` input is **a normalized 0/1 buffer selector**, not the raw PaRAM word: at `0x1181ae6c`/`0x1181ae74` the wrapper constructs `0x01c04014` (PaRAM set 0 `LINK_BCNTRLD`), loads it into `A10` at `0x1181ae80`, constructs constant `0x00044400` at `0x1181aea0`/`0x1181aea4`, and overwrites `A10` with `CMPEQ(A10,0x00044400)` at `0x1181aea8`. `A10` is not reassigned before `0x1181aed8`; the same execution packet as that `CALLP` moves `A10` to `A4` at `0x1181aedc`. Neighboring calls likewise use `MV A10,A4` at `0x1181aeb0`, `0x1181aeb8`, `0x1181aec4`, and `0x1181aed0`. Under ordinary `CALLP` parallel-slot semantics, the reader gets selector `1` when the current PaRAM0 link word is `0x00044400` (set 33's link toward set 32), and `0` otherwise (the configured alternate `0x00044420`, set 32's link toward set 33). This is a static argument derivation, not a live DMA-phase measurement.

The reader constructs `B2=0x11800c00` at `0x1181a398`/`0x1181a3a8`. It forms a **704-byte multiplier** from `192` with bit 9 set (`0x1181a336`/`0x1181a342`), multiplies it by incoming `A4` at `0x1181a348`, and combines it with the base at `0x1181a3ac`–`0x1181a3c0`; the 176-byte multiplier/cancel pair in the same address calculation cancels itself. The normalized 0/1 argument therefore selects `0x11800c00` or `0x11800ec0`. The routine runs `SPLOOPD` with `LDW` at `0x1181a3d6`/`0x1181a3da`, shifts integer words, and applies `INTSP` conversions at `0x1181a3e2`–`0x1181a3f4`. This verifies the **McASP DMA ping-pong buffer-to-floating-point processing boundary** inside IRQ8. Exact lane/channel semantics still need compact-packet and subsequent store tracing; 176-byte B-index in DMA is consistent with 44 32-bit words per lane but is not enough alone to assign deck or mixer names.

The link/selector pairing identifies the completed side if PaRAM reload occurs before the IRQ8 read, as [TI's EDMA LINK rules](https://www.ti.com/lit/ug/spruh91b/spruh91b.pdf) specify: after set 0 (`DST=0x11800c00`) completes, its new link word comes from set 32 (`0x00044420`), giving selector 0 and reading the just-completed base buffer; after set 32 (`DST=0x11800ec0`) completes, the new link word comes from set 33 (`0x00044400`), giving selector 1 and reading the just-completed alternate buffer. The static code fits this completed-buffer handoff. Actual scheduling/order under simultaneous audio events is not measured.

The verified interface for comparing RX3 is narrow: on AZ, McASP0 RX writes alternating 704-byte DSP buffers and IRQ8 reaches integer-to-float processing. Local RX3 notes cover algorithm-level numeric probes, not a matched PaRAM layout or packet contract, so hardware reuse is an open comparison rather than an established shared implementation.
