# IRQ8 audio-trigger checkpoint

The vector's **CPU interrupt slot 8** enters `0x1181ada4`, then at `0x1181ae16` reads EDMA3CC `IPR` (`0x01c01068`). `EXTU.S1 A0,26,26,A0` at `0x1181ae34` keeps the **low six bits**, and `0x1181ae44` writes those bits to `ICR` (`0x01c01070`) to acknowledge pending completion codes 0..5. These are transfer completion code (TCC) bits, not necessarily EDMA channel numbers. [TI's EDMA interrupt chapter](https://www.ti.com/lit/ug/spruh91b/spruh91b.pdf) explicitly allows a channel's TCC to differ from its channel number. The IRQ8 wrapper then calls `0x1181d5ac`, `0x11819880`, staged-control reader `0x1180e644` (`0x1181ae88`–`0x1181ae90`), and further processing routines. Static entry and ordered calls are verified; live invocation frequency is not.

The low-number DMA channels configured in the adjacent setup are **audio serial events**. [TI's C6747 EDMA event table](https://www.ti.com/lit/ds/symlink/tms320c6747.pdf) maps channels/events 0..5 to McASP0/1/2 receive/transmit, with event 0 = McASP0 receive. At `0x11816524`, firmware starts PaRAM set 0 (`0x01c04000`), writes `OPT=0x00100204` at `0x11816546` (bit20 `TCINTEN` set, bit2 `SYNCDIM=AB`), `SRC=0x01d02000` at `0x1181654c`, `ACNT/BCNT=0x00040004` at `0x11816552` (4 elements of 4 bytes per AB event), and `DST=0x11800c00` at `0x11816562`. [TI's memory map](https://www.ti.com/lit/ds/symlink/tms320c6747.pdf) identifies `0x01d02000` as the McASP0 data region. This is a concrete McASP0-data-to-DSP-buffer DMA configuration with completion interrupt enabled.

PaRAM set 0 continues with `SRCBIDX=0`, `DSTBIDX=176` at `0x1181656c` (`0x00b00000`), `LINK=0x4400` (PaRAM set 32), `BCNTRLD=4` at `0x11816588` (`0x00044400`), `SRCCIDX=0`, `DSTCIDX=4` at `0x1181658a` (`0x00040000`), and `CCNT=44` at `0x11816594` (`0x2c`). [TI's `SYNCDIM` definition](https://www.ti.com/lit/ug/spruh91b/spruh91b.pdf) says each AB event transfers `BCNT*ACNT` bytes, so one programmed set spans `44*(4*4)=704` bytes over 44 AB events before its final completion. The 176-byte B stride and 4-byte C stride form a plausible four-lane layout of 44 32-bit words, but that lane interpretation needs buffer consumer verification. The hardware sample clock, linked-set recurrence, and wall-time interrupt cadence remain unmeasured.

The link between PaRAM set 0 and IRQ8's six-bit acknowledgement is strong but **conditional**: `OPT=0x00100204` has `TCC=0` (bits 12..17), so final completion can set `IPR[0]`, exactly inside the handler's low-six mask. [TI's event table](https://www.ti.com/lit/ds/symlink/tms320c6747.pdf) names system event 8 `EDMA3_CC0_INT1` (region 1), but event number 8 and CPU slot 8 are distinct identifiers. The observed handler reads the *global* `IPR`, so its region routing still needs the device's interrupt mux and EDMA DRAE/IER writes checked. No sample rate, block rate, or latency follows from these static dimensions alone.

The same silicon exposes a reusable **interface boundary** for an RX3 investigation: SPI control DMA and McASP audio DMA are separate, verified hardware paths on this AZ DSP. Reuse of packet fields, audio algorithm code, or timing in RX3 requires matching RX3 evidence; none is inferred here.
